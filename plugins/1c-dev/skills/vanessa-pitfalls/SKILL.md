# Грабли Vanessa Automation

Собранные на живых прогонах ловушки, которые съедают часы. Не переоткрывай их прогонами: сверься
со списком. Версии актуальны на сентябрь 2026: Vanessa Automation 1.2.043, платформы 8.3 и 8.5.

## 1. Какой фреймворк

Смотри на версию платформы **базы**, а не конфигуратора:

- **8.5.x: только Vanessa Automation (VA).** Vanessa-ADD падает на
  `ПодключитьОбработчикОжидания`, и параметр `ВыполнятьШагиАссинхронно=Ложь` это не лечит.
- **8.3.x:** работает и ADD, но новые тесты пиши под VA: ADD больше не развивается.

Встроенный MCP-сервер есть в сборках VA начиная с 1.2.043.28. Версия из пакетного менеджера
OneScript (opm) может отставать и приходить без MCP: проверь версию перед тем, как на него
рассчитывать.

## 2. Два режима запуска

| | MCP-режим VA | Прогон через vrunner |
|---|---|---|
| Для чего | писать и отлаживать фичи, смотреть формы живьём | регресс, повторяемый прогон, CI |
| Клиент тестирования | живёт между прогонами | поднимается и гасится каждый раз |
| Скорость | первый прогон долгий, каждый следующий в разы быстрее | каждый раз с нуля |
| Мышь | свободна | занята автокликером, трогать нельзя |

Правило: правишь фичу, гоняешь через MCP; убедился, прогоняешь через vrunner, он и есть регресс.

## 3. MCP-режим: подготовка и грабли

Подготовка базы (разово): расширение транспорта MCP загружено, у расширения **снят безопасный
режим** (иначе внешняя компонента транспорта не подключится), у тестового пользователя снята
защита от опасных действий. Инструменты приносит сама обработка VA, поэтому VA и MCP обязаны
жить в одном сеансе: менеджер тестирования запускается с `/TESTMANAGER` и `/Execute` на
обработку VA с параметром запуска MCP.

Рабочий цикл: загрузить фичи, запустить сценарий, поправить фичу, запустить снова. Клиент между
прогонами не закрывай: на нём вся экономия времени. Полезные инструменты: анализ формы
(дерево элементов, готовые шаги Gherkin, данные таблицы), выполнение одного шага по номеру
строки, `search_for_steps_by_keywords`, база знаний VA прямо из сессии.

Грабли:

- **`ИнтервалВыполненияШага = 0` вешает VA**: прогон не доходит до первого шага, сеанс
  перестаёт отвечать даже на запрос состояния. Держи 1.
- **Жёсткий порт в шаге подключения клиента** не даёт переиспользовать уже поднятый клиент: VA
  стартует новый на занятом порту и висит до таймаута. Порт в Контексте фичи не задавай.
- **Закрытие клиента через MCP оставляет мёртвый PID** в таблице клиентов: повторное
  подключение не пройдёт, пока PID не обнулить руками.
- **Настройки VA не переживают перезапуск сеанса**: таблица клиентов обнуляется. Клиента
  надёжнее подключать из Контекста фичи, а не из профиля.
- **Файл VBParams для MCP нужен отдельный.** В файле для регресса обычно стоят
  `ВыполнитьСценарии: Истина` и `ЗавершитьРаботуСистемы: Истина`: с ним сеанс отработает фичи на
  старте и закроется.
- **MCP-клиент агента не всегда переподключается** после падения сеанса 1С. Инструменты доступны
  напрямую: POST на адрес MCP, JSON-RPC, заголовок `Mcp-Session-Id` из ответа `initialize`
  (без него ответ «Unexpected message, expect initialize request»).

## 4. vrunner: чек-лист перед прогоном

1. Конфигуратор и лишние сеансы 1С закрыты, MCP-сеансы тоже: автокликер жмёт «Да» и «ОК» во
   всех окнах 1С. Мышь во время прогона не трогать.
2. Логин и пароль тестового пользователя заданы переменными окружения, не в командной строке.
3. Скрипт запуска вызывается напрямую из оболочки. Обёртка `.cmd`, сохранённая в UTF-8 с BOM, из
   PowerShell через `&` не стартует.
4. Итог смотри по коду возврата и файлу статуса сборки: 0 успех, 2 упали шаги, 3 не загружено
   ни одного сценария. Каша в консоли это конфликт кодировок cp866 и UTF-8 при выводе, сам файл
   лога читается как UTF-8.

## 5. Кодировки: три жёстких правила

- **Feature-файлы строго UTF-8 с BOM.** Без BOM разбор Gherkin ломается, и прогон пишет
  «Сценарии для выполнения не загружены. Проверьте тег» при правильных тегах.
- **VBParams JSON: UTF-8 с BOM и без ключа `$schema`.** VA читает JSON в Структуру 1С, а
  `$schema` недопустимое имя ключа: «Не удалось прочитать файл настроек JSON».
- **Кириллица из переменной среды до фичи не доезжает**: шаг чтения переменной даёт кракозябры.
  Кириллические значения пиши литералом в фиче, через переменные среды передавай только
  латиницу (например, пароль).

## 6. Тест-клиент не знает пароль

Штатный шаг запуска тест-клиента стартует его с `/N` без `/P`: клиент висит на окне входа, и
прогон падает с «Прерывание по таймауту». Порт при этом слушается: не верь порту, смотри на окно.

Рабочий Контекст:

```gherkin
Контекст:
	Дано Я запоминаю значение переменной среды 'ONEC_PASSWORD' в переменную 'ПарольПользователя'
	Когда Я подключаю клиент тестирования с параметрами:
		| 'Имя подключения' | 'Имя компьютера' | 'Логин'           | 'Пароль'               | 'Тип клиента' |
		| 'Тест'            | 'localhost'      | 'ТестПользователь' | '$ПарольПользователя$' | 'Тонкий'      |
	И я закрываю все окна клиентского приложения
```

Порт намеренно не задан (см. раздел 3). Пустая строка соединения берётся из базы менеджера.
Параметр `ТаймаутЗапуска1С` подними до 300: стандартных 25 секунд холодному тонкому клиенту к
серверной базе не хватает.

## 7. Диалект шагов VA отличается от ADD

Части шагов ADD в VA нет, например «Я запускаю тест-клиент для пользователя … с паролем …» и
«открылась форма с именем …». Проверенные шаги VA:

- `Я открываю основную форму списка документа "Имя"` и то же для справочника
- `в таблице "Список" я перехожу к строке:` с таблицей колонка и значение
- `в таблице "Список" я выбираю текущую строку`
- `в поле с именем 'X' я ввожу текст "Y"`; для ссылочного поля надёжнее
  `из выпадающего списка с именем "X" я выбираю по строке 'Значение'`
- `я нажимаю на кнопку с именем 'X'`
- `элемент формы с именем "X" стал равен 'Значение'`
- `я устанавливаю флаг с именем 'X'` и `я снимаю флаг с именем 'X'`
- `я закрываю текущее окно` и `я закрываю все окна клиентского приложения`
- `Тогда открылось окно "Заголовок"`: обычно не нужен, следующий шаг по элементу и так упадёт,
  если форма не открылась
- `Я запоминаю значение выражения "…" в переменную "X"`: умеет вызывать серверные общие модули
  конфигурации с вызовом сервера, это основной канал подготовки данных. Часть платформенных
  функций не умеет. Если выражение не вычислилось, VA молча кладёт в переменную **сам текст
  выражения**: ошибка «в таблице не найдена строка со значением `Модуль.Функция()`» значит, что
  такой функции нет в базе.

**Новую формулировку шага не угадывай прогоном.** Ищи её через MCP
(`search_for_steps_by_keywords`) или поиском по эталонным фичам в пакете VA: каталоги
`features/Support/Templates`, `features/Core/TestClient`, `features/Libraries`. Параметры
VBParams описаны в пакете VA в `docs/JsonParams/JsonParamsRU.md`.

## 8. Данные для UI-сценария готовь фикстурой

Подготовку делай серверной функцией расширения с вызовом сервера через шаг «значение
выражения», верни номер или ключ и работай в интерфейсе по нему. Требования к такой фикстуре
отличаются от хелперов YAxUnit:

- **идемпотентность**: справочные элементы ищи по наименованию и создавай только при
  отсутствии, иначе после десяти прогонов в выпадающем списке десять одинаковых элементов;
- **фиксированные наименования** без GUID: фича выбирает значение из списка по строке;
- **без транзакции с откатом**: данные должны остаться в базе, иначе форма их не покажет;
- **самоочистка в начале**: удали документы прошлых прогонов по тексту-маркеру вместе с
  записями независимых регистров, за документом они не уходят.

Помни про отборы форм: если список фильтрует по пользователю, подразделению или статусу,
тестовый документ может быть не виден (ошибка «Не удалось перейти к нужной строке»). Либо
готовь данные под отбор, либо снимай отбор шагом в интерфейсе.

## 9. Прогон для новой базы

1. Скопируй файл VBParams: без `$schema`, с `ТаймаутЗапуска1С`, поправь пути отчётов и теги.
2. Скопируй фичу-шаблон с Контекстом из раздела 6, свой тег в шапке и в `СписокТеговОтбор`.
3. В скрипте запуска поменяй базу, версию платформы базы (от неё же выбор фреймворка, раздел 1)
   и пути к фичам, настройкам и отчётам.
4. Все новые файлы сохраняй в UTF-8 с BOM.
