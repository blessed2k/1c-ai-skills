# Исключения: перехват и вызов

Стандарты #std499 (перехват исключений) и #std790 (вызов исключений), обновлены в 2024 году.

## Перехват

- По умолчанию исключения **не перехватывают**. Платформа сама покажет сообщение
  пользователю, запишет подробности в журнал регистрации и при необходимости отправит отчёт
  в сервис регистрации ошибок.
- Перехват оправдан, когда технический текст непонятен и его нужно дополнить прикладным
  смыслом: недоступен внешний ресурс, сбой веб-сервиса, почты, принтера, криптографии,
  некорректные входные данные. Тогда исключение перехватывают **локально**, вокруг конкретного
  вызова, и пробрасывают дальше с уточнением, не теряя исходную ошибку.
- Большие блоки `Попытка` вокруг длинного кода недопустимы: они ловят чужие ошибки.
- Нельзя разбирать текст исключения, чтобы понять причину: текст зависит от языка и версии.
  Для этого есть категории и коды ошибок (ниже).
- Пустой `Исключение КонецПопытки` запрещён. Если ошибку действительно нужно подавить,
  объясни это комментарием и запиши её в журнал регистрации.

## Какими функциями описывать ошибку

| Задача | Использовать | Не использовать |
|---|---|---|
| подробности для журнала регистрации (со стеком) | `ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())` | `ОписаниеОшибки()`: в нём нет стека |
| текст для пользователя | `ОбработкаОшибок.СообщениеОбОшибкеДляПользователя(ИнформацияОбОшибке())` | `ОбработкаОшибок.КраткоеПредставлениеОшибки(...)`: теряет уточнения, добавленные при пробросе |

У объекта `ИнформацияОбОшибке` **нет** методов `ПодробноеПредставлениеОшибки` и
`КраткоеПредставлениеОшибки`: вызов `ИнформацияОбОшибке().ПодробноеПредставлениеОшибки()`
упадёт во время выполнения. Функции вызываются из `ОбработкаОшибок` с объектом ошибки в
параметре. Из методов у объекта есть `ЯвляетсяОшибкойКатегории`, из свойств `Описание`,
`Причина`, `Код`, `ДополнительнаяИнформация`.

## Проброс с уточнением

Расширенная форма `ВызватьИсключение(Текст, Категория, Код, ДляАдминистратора, Причина)`
позволяет передать исходную ошибку в параметре `Причина`, чтобы она не потерялась.

С БСП уточнение строится функцией `ОбщегоНазначенияКлиентСервер.УточнениеИсключения`:

```bsl
Попытка
	ЗагрузитьКурсыСоСервера(Адрес);
Исключение
	Ошибка = ИнформацияОбОшибке();
	Уточнение = ОбщегоНазначенияКлиентСервер.УточнениеИсключения(Ошибка,
		НСтр("ru = 'Не удалось загрузить курсы валют:'"));
	ВызватьИсключение(Уточнение.Текст, Уточнение.Категория, , , Ошибка);
КонецПопытки;
```

Без БСП текст для пользователя берут из `ОбработкаОшибок.СообщениеОбОшибкеДляПользователя`,
добавляют к нему прикладное пояснение и передают исходную ошибку в `Причина`.

## Когда обработать, а не пробросить

В особых сценариях (например, обработчики обновления) ошибку обрабатывают сами. Тогда:
программные ошибки отправляют в сервис регистрации (`ИнформацияОбОшибке.ЯвляетсяОшибкойКатегории`,
`ОтчетОбОшибке.Отправить`), в журнал пишут подробное представление, пользователю показывают
сообщение для пользователя.

## Вызов

- Исключение бизнес-логики, которое читает пользователь: категорию не указывают.
- Остальным исключениям указывают подходящую категорию `КатегорияОшибки` (сеть, принтер,
  нарушение прав и т.п.): пользователь получит типовые рекомендации.
- Ошибки программиста (неверный тип параметра, неправильно встроенная подсистема):
  категория `КатегорияОшибки.ОшибкаКонфигурации`.
- Проверка прав: обычно `ВыполнитьПроверкуПравДоступа`. Если исключение вызывается вручную,
  то с категорией `НарушениеПравДоступа`, а пояснение для администратора передаётся отдельно
  от текста для пользователя.
- Если вызывающему коду нужно отличать ошибки:
  - вернуть **строковый** код результата вместо исключения (числовые коды запрещены);
  - или анализировать категорию ошибки платформы через `ЯвляетсяОшибкойКатегории`;
  - или передать строковый код третьим параметром `ВызватьИсключение` с префиксом подсистемы
    (`МояПодсистема.НетСвязиССервером`) и проверять `ИнформацияОбОшибке().Код`. С БСП коды во
    вложенных причинах ищет `ОбщегоНазначенияКлиентСервер.ЭтоИсключениеСКодомОшибки`.

## Исключение или Отказ

В `ОбработкаПроверкиЗаполнения`, `ОбработкаПроведения`, `ПередЗаписью`, `ПриЗаписи`,
`ПередУдалением` для ошибок, которые пользователь может исправить, **не вызывают исключение**:
ставят `Отказ = Истина` и выводят сообщение. Так пользователь видит все причины сразу.
Исключение уместно, только если пользователь не может исправить ситуацию в этой операции или
ошибка делает остальные проверки бессмысленными.
