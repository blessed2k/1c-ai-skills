# Файлы: временные файлы, двоичные данные, безопасность

Стандарт #std542 (переработан в июле 2026 года).

## Временные файлы и каталоги

- Имя временного файла только через `ПолучитьИмяВременногоФайла`. Временный каталог создают по
  имени, полученному тем же методом.
- В веб-клиенте метода нет: имя строят из `КаталогВременныхФайлов()` и `Новый УникальныйИдентификатор`,
  с БСП используют `ФайловаяСистемаКлиент.СоздатьВременныйКаталог`.
- Удаляй файл сам после работы, на автоудаление не рассчитывай. С БСП:
  `ФайловаяСистема.УдалитьВременныйФайл`, `ФайловаяСистема.УдалитьВременныйКаталог`.
- На сервере вся работа с временным файлом завершается **в одном серверном вызове**: в
  кластере следующий вызов может выполниться на другом компьютере. Между вызовами данные
  держат во временном хранилище (`ПоместитьВоВременноеХранилище`).
- Большие файлы между сеансами (фоновые задания, веб-сервисы): общий каталог для всего
  кластера, учёт файлов, удаление и регламентная очистка. С БСП:
  `ФайловаяСистема.ОбщийКаталогВременныхФайлов`.

## Двоичные данные без диска

Если нужно получить двоичные данные из текста, XML, JSON и т.п., временный файл не нужен:
пиши в поток в памяти.

```bsl
Поток = Новый ПотокВПамяти;
Документ = Новый ТекстовыйДокумент;
Документ.УстановитьТекст(ТекстОтчета);
Документ.Записать(Поток, КодировкаТекста.UTF8);
ДвоичныеДанные = Поток.ЗакрытьИПолучитьДвоичныеДанные();
```

Поток после чтения обязательно закрывают. Временный файл оправдан, только если платформа не
умеет получить данные иначе как через файл.

## Файл между клиентом и сервером

У клиента и сервера разные файловые системы, поэтому файл передают через временное хранилище:

- с клиента на сервер: `ПоместитьФайлНаСерверАсинх` (и групповые варианты), с БСП
  `ФайловаяСистемаКлиент.ЗагрузитьФайл`. Чтобы данные жили несколько серверных вызовов,
  передают идентификатор формы;
- с сервера на клиент: `ПолучитьФайлССервераАсинх`, с БСП `ФайловаяСистемаКлиент.СохранитьФайл`.

## Имена файлов

Имена, которые формирует код, только латиницей и цифрами, текст в UTF-8 (кроме чужих форматов).
Если имя вводит пользователь, разреши кириллицу, но предложи латинский вариант. С БСП
транслитерация: `СтроковыеФункцииКлиентСервер.СтрокаЛатиницей`.

## Безопасность

- **Нельзя** хранить путь или имя файла в реквизите формы: клиент можно подменить, и сервер
  прочитает или перезапишет произвольный файл.
- **Нельзя** принимать путь к файлу параметром серверной процедуры формы или экспортной
  процедуры серверного общего модуля: их можно вызвать с клиента сторонними средствами.
  Передавай на сервер адрес во временном хранилище, а не путь.
- Расширение файла с клиента проверяй по списку допустимых на сервере или очищай
  `ОбщегоНазначенияКлиентСервер.ЗаменитьНедопустимыеСимволыВИмениФайла`. Так же очищай имена,
  собранные из данных базы.
- Перед работой с файлом на сервере убедись, что он лежит во временном каталоге или в
  предусмотренном хранилище (проверка начала полного пути).
- В каталог программы (`КаталогПрограммы()`) ничего не пишут.
- Доступ сервера к файлам ограничен правами пользователя ОС, под которым работает сервер 1С
  (или веб-сервер для опубликованной файловой базы).
