# Обработчики событий объекта

Стандарты #std773 (признак `ОбменДанными.Загрузка`), #std464 (`ПередЗаписью`), #std790 п. 3
(исключение или `Отказ`).

## ОбменДанными.Загрузка

- В `ПередЗаписью`, `ПриЗаписи`, `ПередУдалением` модуля объекта (и в подписках на эти
  события) **первым делом** проверяют признак загрузки и выходят:

```bsl
Процедура ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)
	Если ОбменДанными.Загрузка Тогда
		Возврат;
	КонецЕсли;
	// проверки и дозаполнение реквизитов
КонецПроцедуры
```

- Смысл: при записи с этим признаком (обмен, загрузка базы из XML, сервисные механизмы) объект
  должен записаться «как есть», будто обработчика нет. Бизнес-логика уже отработала там, где
  объект создан.
- Исключение: механизм обмена, который при загрузке регистрирует данные для других узлов. С
  БСП отключить регистрацию можно дополнительным свойством объекта
  `ОтключитьМеханизмРегистрацииОбъектов`. Другие исключения из правила поясняют комментарием.
- Код, который ставит объекту `ОбменДанными.Загрузка = Истина`, сам отвечает за целостность
  объекта: дозаполнение выносят в экспортные процедуры объекта и вызывают перед записью.

## Что делать в ПередЗаписью

Заполнение реквизитов, проверки и сравнение со «старыми» значениями из базы (для уже
записанных объектов). Проверки, которым не нужна транзакция, делают в
`ОбработкаПроверкиЗаполнения`, вне транзакции записи.

## Исключение или Отказ

Для ошибок, которые пользователь может исправить, ставят `Отказ = Истина` и выводят
сообщение, а не вызывают исключение: пользователь увидит все причины сразу. Исключение
уместно, если пользователь не может исправить ситуацию в этой операции (подробнее в
`errors.md`).

## Транзакция

Эти обработчики уже выполняются внутри системной транзакции: свою транзакцию в них не
открывают, блокировки ставят сразу (см. `transactions.md`).
