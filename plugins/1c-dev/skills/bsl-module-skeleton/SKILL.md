# Структура модуля 1С

Стандарты #std455 (структура модуля) и #std439 (директивы компиляции и препроцессор).
Порядок областей у разных видов модулей разный, и по памяти его легко перепутать: бери его
отсюда.

## Порядок разделов в целом

1. Заголовок модуля: комментарий с назначением и условиями применения. У модуля формы в
   заголовке рекомендуется описать параметры формы.
2. Описание переменных.
3. Программный интерфейс.
4. Обработчики событий (объекта или формы).
5. Служебные процедуры и функции.
6. Инициализация.

Разделы оформляются областями (`#Область ... #КонецОбласти`) с именами по правилам имён
переменных. Большие разделы делят на вложенные области по смыслу (например,
`ОбновлениеИнформационнойБазы` внутри служебных процедур).

**В готовом модуле не должно быть пустых областей.** Шаблоны ниже это заготовки: области,
которые не понадобились, из готового модуля удаляют.

Описание переменных и инициализации нет в неглобальных общих модулях, модулях менеджеров,
наборов записей, менеджеров значений констант и в модуле сеанса.

## Общий модуль

```bsl
#Область ПрограммныйИнтерфейс
#КонецОбласти

#Область СлужебныйПрограммныйИнтерфейс
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
#КонецОбласти
```

## Модуль объекта, менеджера, набора записей, обработки, отчёта

```bsl
#Область ОписаниеПеременных
#КонецОбласти

#Область ПрограммныйИнтерфейс
#КонецОбласти

#Область ОбработчикиСобытий
#КонецОбласти

#Область СлужебныйПрограммныйИнтерфейс
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
#КонецОбласти

#Область Инициализация
#КонецОбласти
```

Для модулей, где переменных и инициализации быть не может (менеджер, набор записей), эти две
области не создают.

## Модуль формы

```bsl
#Область ОписаниеПеременных
#КонецОбласти

#Область ОбработчикиСобытийФормы
#КонецОбласти

#Область ОбработчикиСобытийЭлементовШапкиФормы
#КонецОбласти

#Область ОбработчикиСобытийЭлементовТаблицыФормы<ИмяТаблицы>
#КонецОбласти

#Область ОбработчикиКомандФормы
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
#КонецОбласти
```

Для каждой таблицы формы своя область: `ОбработчикиСобытийЭлементовТаблицыФормыТовары`,
`ОбработчикиСобытийЭлементовТаблицыФормыУслуги` и т.д.

## Модуль команды

```bsl
#Область ОбработчикиСобытий
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
#КонецОбласти
```

В `ОбработчикиСобытий` лежит `ОбработкаКоманды`.

## Что в какой раздел

| Раздел | Что внутри |
|---|---|
| `ПрограммныйИнтерфейс` | экспортные методы для других объектов конфигурации и внешних программ. Методы, которые вызываются только из самого объекта, его форм и команд, сюда **не** кладут: им место в служебных |
| `ОбработчикиСобытий` | обработчики событий объекта или менеджера (`ПередЗаписью`, `ОбработкаПроведения` и т.п.), желательно в порядке их описания в синтакс-помощнике |
| `СлужебныйПрограммныйИнтерфейс` | экспортные методы, которые можно вызывать только из других подсистем той же библиотеки (конфигурации) |
| `СлужебныеПроцедурыИФункции` | внутренняя реализация модуля. Если модуль входит в подсистему из нескольких объектов, здесь же допустимы экспортные методы только для объектов этой подсистемы |
| `ОписаниеПеременных` | переменные модуля, у каждой комментарий в той же строке |
| `Инициализация` | операторы, инициализирующие переменные модуля или объект |

В модуле формы:

- у каждого события свой обработчик. Общие действия выносят в отдельную процедуру и вызывают
  её из обработчиков, а не вызывают один обработчик из другого;
- обработчики одного элемента держат рядом, в порядке панели свойств;
- служебные процедуры группируют по смыслу, а не по «клиентские, серверные, без контекста».

## Директивы и препроцессор

- Директивы `&НаКлиенте`, `&НаСервере`, `&НаСервереБезКонтекста` пишут только в модулях форм и
  команд. В остальных модулях контекст задают свойства модуля или инструкции препроцессора.
- В общих модулях с признаками «Клиент» и «Сервер» одновременно **нельзя** ветвиться через
  `#Если Сервер` или `#Если Клиент`: контекст там не определяется надёжно. Разное поведение
  разносят по модулям с постфиксами `Клиент` и `Сервер`, общий код оставляют в
  `КлиентСервер`. Ветвление по виду клиента (`#Если ВебКлиент`) допустимо.
- Инструкции препроцессора и области не должны разрывать конструкции: выражение, блок
  `Если`, объявление процедуры, список параметров вызова.
- Типовые конфигурации дополнительно оборачивают серверные модули объектов в
  `#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда ... #КонецЕсли`.
  Стандарт 455 этого не требует: следуй тому, как оформлены соседние модули конфигурации.

## Пример процедуры программного интерфейса

```bsl
#Область ПрограммныйИнтерфейс

// Возвращает остаток товара на складе на текущий момент.
//
// Параметры:
//  Номенклатура - СправочникСсылка.Номенклатура - товар.
//  Склад - СправочникСсылка.Склады - склад.
//
// Возвращаемое значение:
//  Число - остаток в базовых единицах.
//
Функция ОстатокТовара(Номенклатура, Склад) Экспорт
	// ...
КонецФункции

#КонецОбласти
```

Если вид модуля не из перечисленных, скажи об этом и возьми ближайший шаблон по назначению
модуля, явно назвав допущение.
