# 1c-ai-skills v0.1: спецификация

## Задача

Выложить набор скиллов для ИИ-разработки на 1С так, чтобы его мог поставить и понять незнакомый
человек. Исходник: рабочий набор адаптаций mattpocock/skills (grilling, to-spec, to-tickets,
implement) и заметки по Vanessa Automation. Публичный репозиторий становится единственным
источником правды для этих скиллов.

## Решение

Маркетплейс Claude Code с одним плагином `1c-dev`. Скиллы обезличены и не зависят от конкретного
MCP-сервера: основной путь к фактам идёт через XML-выгрузку конфигурации, MCP подключается как
вариант. Всё личное (режим правок, маркер авторства, место хранения спек, команды проверок) живёт
в файле настроек, который создаёт `/1c-dev:setup`.

## Состав

```
1c-ai-skills/
├── README.md, README.en.md, LICENSE (MIT), THIRD_PARTY_NOTICES.md, CHANGELOG.md
├── .claude-plugin/marketplace.json
├── plugins/1c-dev/
│   ├── .claude-plugin/plugin.json
│   └── skills/{grill, spec, tickets, step, vanessa-pitfalls, setup}/SKILL.md
└── docs/{workflow.md, settings.md, requirements.md, specs/}
```

| Скилл | Основа | Что меняется |
|---|---|---|
| `grill` | grilling + grill-me | Один скилл. Факты из выгрузки через поиск, MCP как вариант |
| `spec` | to-spec | Обращение к пользователю вместо имени. Место хранения из настроек. Без ссылок на несуществующие инструменты и личные проекты |
| `tickets` | to-tickets | Исполнители из настроек. Шаги чекбоксами в файле спеки |
| `step` | implement (work) | Режим правок и маркер авторства из настроек. Проверки из настроек, иначе явная пометка «не проверено» |
| `vanessa-pitfalls` | заметки Vanessa | Только общие знания: кодировки, VBParams, пароль тест-клиента, интервал шага, диалект VA и ADD, фикстуры, выбор фреймворка по версии платформы. Без путей, баз, портов и скриптов |
| `setup` | новый | Интервью, пишет файл настроек проекта или глобальный |

## Настройки

Порядок поиска: `.claude/1c-dev.md` в проекте, затем `~/.claude/1c-dev.md`, затем значения по
умолчанию с подсказкой запустить `/1c-dev:setup`.

| Поле | По умолчанию |
|---|---|
| Режим правок | листинг под вставку в конфигуратор |
| Маркер авторства | нет |
| Хранилище спек | `docs/specs/` |
| Команды проверок | нет: шаг закрывается с пометкой «не проверено» |
| Путь к выгрузке | нет: скилл спрашивает |
| MCP для 1С | нет |
| Исполнители | агент, человек; можно добавить своих и скилл передачи |

## Данные и безопасность

Скиллы не пишут в базы 1С. `step` сохраняет запрет: без явного разрешения и подтверждённой базы
ничего не загружается, не обновляется и не пишется. В репозитории нет секретов, персональных
данных, следов рабочего контура и личных инструментов (список строк держится вне репозитория).
История git начинается с нуля.

## Чем проверяем

1. Поиск по списку запрещённых строк: 0 совпадений.
2. `claude plugin validate` зелёный; плагин ставится из локального маркетплейса, все шесть
   скиллов видны как `1c-dev:*`.
3. `claude plugin eval` с кейсами: скилл без файла настроек не падает и подсказывает `setup`;
   `step` без команд проверок пишет «не проверено».
4. Ручной прогон цикла `setup → grill → spec → tickets → step` на демо-конфигурации с БСП.
5. Скан секретов перед первым пушем.

Ограничение: пункт 4 ручной, поведение модели в полном цикле тестом не закрыто.

## Вне рамок

Публикация MCP-сервера, скилл постановки задачи разработчику, анти-слоп для текстов, скрипты
запуска Vanessa, гарантии для агентов кроме Claude Code, английская версия скиллов.
