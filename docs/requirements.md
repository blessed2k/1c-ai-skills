# Требования и инструменты

Скиллы опираются на то, что есть в окружении, и работают тем лучше, чем больше им доступно.
Обязательный только Claude Code.

| Инструмент | Что даёт | Что будет без него |
|---|---|---|
| Claude Code с плагинами | установка и запуск скиллов командами `/1c-dev:*` | скиллы можно скопировать вручную, но это не проверялось |
| XML-выгрузка конфигурации | агент сам проверяет структуру объектов, места использования, код модулей, права | факты придётся подтверждать вам, спека пишется без сверки |
| git | история правок, откат шага, режим `files` | работайте в режиме `listing` |
| MCP-сервер для 1С | быстрый доступ к структуре, движениям и правам вместо поиска по XML | агент ищет по выгрузке, медленнее и дороже по токенам |
| YAxUnit | проверка логики после шага | шаг закрывается с пометкой «не проверено» или ручной проверкой |
| Vanessa Automation | проверка пользовательских сценариев | то же |
| vrunner (vanessa-runner) | запуск синтаксической проверки, YAxUnit и Vanessa из командной строки | проверки придётся запускать вручную |

## Выгрузка конфигурации

Выгрузку в XML можно получить из конфигуратора («Конфигурация» → «Выгрузить конфигурацию в
файлы») или командой пакетного режима `DESIGNER /DumpConfigToFiles`. Путь к ней укажите в
настройке `dump_path`. Для типовой конфигурации выгрузка большая: держите её вне основного
репозитория или выгружайте только объекты, которые трогает задача.

## Проверки

Команды проверки задаются в настройке `checks`, по одной на строку. Агент запускает их после
каждого шага и приводит в отчёте код возврата. Пароли передавайте через переменные окружения,
не пишите их в команду: текст команды попадает в журналы.

Скилл не заменяет прогон на базе. Статическая проверка и ревью не ловят ошибки компиляции и
реальное поведение платформы, поэтому в отчёте агент отдельно пишет, что осталось непроверенным.
