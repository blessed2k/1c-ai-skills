# Изменения

## 0.2.0

- Скилл `bsl-standards`: правила стандартов ИТС, на которых агент ошибается или которые
  появились в 2023-2026 годах. Темы: исключения (#std499, #std790), транзакции и ответственное
  чтение (#std783, #std648), запись регистров режимами замещения (#std792), файлы и их
  безопасность (#std542), длительные операции (#std642), клиент-сервер (#std487, #std678),
  запросы (#std733, #std726, #std436), HTTPS и внешний код (#std669, #std794), обработчики
  записи (#std773, #std464). Тема проверки прав (#std737) не вошла: без скилла агент и так
  пишет её по стандарту.
- Скилл `bsl-module-skeleton`: структура модуля по #std455 и #std439, включая модуль команды,
  области таблиц формы и запрет пустых областей.
- Скилл `yaxunit-test-skeleton`: заготовка тестового модуля YAxUnit.
- `step` подсказывает, какой справочный скилл открыть перед кодом.
- Сравнительные eval-кейсы справочных скиллов (`evals-knowledge`): каждая тема проверена
  прогоном со скиллом и без него.

## 0.1.1

Первый выпуск. Доработан по итогам ручного прогона внутренней версии 0.1.0 на демо-конфигурации.

- Задача без кода не заводит цикл в тупик: `grill` называет такой исход, `spec` сохраняет
  «решение без кода» с шагами для человека, `step` перечисляет эти шаги и не отправляет обратно.
- Определено, что считается корнем проекта. Без корня `spec`, `tickets` и `step` спрашивают, куда
  сохранять и где искать спеку, а не пишут в случайную папку.
- `setup` учитывает папку с несколькими проектами: общие поля в личный файл, пути в файл проекта.
- В командах `checks` работают подстановки `{dump_path}` и `{project_root}`.
- Формат настроек перенесён внутрь скилла `setup`, чтобы он был доступен в установленном плагине.
- Отчёты прогонов eval больше не пишутся в каталог плагина.

  переработаны из mattpocock/skills под 1С.
- Скилл `vanessa-pitfalls`: грабли Vanessa Automation.
